## 2. 项目背景

博创网官网是博士后创新创业陪伴系统的公开展示入口，面向博士后创业者、赛事参与者、政府/园区/高校/合作机构等外部用户，提供平台介绍、赛事动态、服务产品、合作机构和新闻资讯展示。

当前官网前端已经具备 mock 数据展示能力，并预留 `VITE_BC_SITE_API_BASE_URL` 接入真实接口。后续需要在保证桌面端展示完整性的同时，强化移动端真实使用体验，移动端不作为报名/登录入口，仅提供公开信息浏览和赛事详情查询。

## 3. 产品目标

1. 建立统一、可信的官网门面，清晰表达博创网对博士后创新创业的服务能力。
2. 展示赛事和人才项目，让用户可快速了解赛事状态、时间、地点、奖金、赛道、详情与进程。
3. 展示新闻资讯、政策动态、赛事动态和产业观察内容，形成可持续运营的内容入口。
4. 移动端提供适合手指操作的浏览体验，包括简洁首屏、横向滑动栏目、赛事轮播拖动反馈和大幅度纵向滑动定位。
5. 为后续 CMS、赛事管理后台或官网后端接口接入预留清晰的数据结构和接口边界。

## 4. 用户角色

| 用户角色 | 主要诉求 | 关键入口 |
|---|---|---|
| 博士后/创业团队 | 查看赛事信息、了解参赛要求、准备材料、关注政策动态 | 首页、赛事列表、赛事详情、新闻资讯 |
| 政府/园区/高校 | 了解平台能力、合作资源、赛事运营服务 | 首页生态体系、服务产品、合作机构 |
| 赛事运营人员 | 发布或维护赛事信息、资讯内容、合作信息 | 后续 CMS/后台接口 |
| 普通访客 | 快速了解博创网定位、品牌能力和最新动态 | 首页首屏、新闻资讯 |

## 7. 移动端专项需求

### 7.1 总体原则

1. 移动端需要按手机浏览和手指操作重新设计，不只是把 PC 卡片改成单列。
2. 移动端首屏需要简洁，避免组件半露、内容拥挤和首屏视觉噪声。
3. 横向栏目必须具备明确的卡片定位和滑动反馈，不能只是普通横向滚动。
4. 移动端取消登录、工作台和赛事报名入口；赛事信息仍可完整查看。

### 7.2 横向滑动栏目

| 栏目 | 需求 |
|---|---|
| Live Competitions | 支持手指拖动，拖动过程卡片跟随手指移动，释放后吸附到下一张/上一张 |
| Competitions | 动画逻辑与生态体系、服务产品一致，拖动时即时反馈，不等释放后才播放动画 |
| Ecosystem | 横向滑动卡片，释放后定位到完整卡片 |
| Services | 横向滑动卡片，释放后定位到完整卡片 |
| Partners | 横向滑动展示合作机构，卡片视觉适配移动端 |
| News | 横向滑动资讯卡片，释放后定位到完整卡片 |

### 7.3 纵向滑动定位

移动端首页支持识别大幅度纵向滑动。当用户在非横向滑动区域进行明显上滑/下滑时，页面应自动定位到下一个或上一个 section。

判定规则建议：

| 条件 | 说明 |
|---|---|
| 触发端 | 仅移动触控端 |
| 滑动距离 | 纵向滑动距离达到阈值后触发 |
| 方向判断 | 纵向位移需明显大于横向位移，避免和横向卡片冲突 |
| 排除区域 | 横向滑动区域内不触发 section 跳转 |
| 动画 | 使用平滑滚动，滚动期间加锁避免连续误触发 |

### 7.4 移动端入口限制

| 入口 | 移动端表现 |
|---|---|
| 登录按钮 | 不展示 |
| 工作台入口 | 不展示 |
| 报名赛事按钮 | 不展示 |
| 赛事详情 | 保留完整信息展示 |
| 大赛列表 | 保留筛选、查看详情能力 |

## 8. 数据与接口需求

当前前端接口层位于 `src/api/site.ts`，配置 `VITE_BC_SITE_API_BASE_URL` 后优先请求真实接口，失败时使用 mock 数据兜底。

| 接口 | 方法 | 用途 | 返回类型 |
|---|---|---|---|
| `/site/home` | GET | 获取首页聚合数据 | `SiteHomeData` |
| `/site/competitions` | GET | 获取赛事列表 | `SiteCompetition[]` |
| `/site/competitions/:slug` | GET | 获取赛事详情 | `CompetitionDetail` |
| `/site/news` | GET | 获取资讯列表 | `SiteNewsArticle[]` |
| `/site/news/:slug` | GET | 获取资讯详情 | `SiteNewsArticle` |

### 8.1 首页数据

`SiteHomeData` 包含：

| 字段 | 说明 |
|---|---|
| `navItems` | 导航菜单 |
| `stats` | 首页统计数据 |
| `ecosystem` | 生态体系卡片 |
| `competitions` | 赛事列表 |
| `products` | 服务产品卡片 |
| `news` | 新闻资讯 |
| `partners` | 合作机构 |

### 8.2 赛事数据

赛事基础字段包括：`id`、`slug`、`name`、`status`、`time`、`trackDescription`、`metric`、`summary`、`location`、`deadline`、`reward`、`rewardUnit`、`tags`、`image`、`category`、`tracks`。

赛事详情补充字段包括：`intro`、`objective`、`eligibility`、`milestones`、`materials`、`services`。

### 8.3 资讯数据

资讯字段包括：`id`、`slug`、`type`、`title`、`date`、`summary`、`author`、`body`。

## 9. 非功能需求

| 类型 | 要求 |
|---|---|
| 响应式 | 支持主流移动端和桌面端视口，不出现文字溢出、按钮遮挡、卡片半露等问题 |
| 可访问性 | 保留语义化链接和按钮，支持键盘基础导航，图片需具备合理替代语义或装饰处理 |
| 性能 | 首页动画和轮播需避免明显卡顿，移动端滑动反馈需跟手 |
| 兼容性 | 支持现代 Chromium、Safari、Firefox 浏览器 |
| 容错 | 未配置接口或接口失败时使用 mock 数据兜底 |
| 安全 | 官网展示页不在移动端暴露报名/登录入口；接口配置不应泄露敏感信息 |

## 10. 验收标准

### 10.1 页面验收

1. `/` 首页所有 section 可正常展示，PC 和移动端均无布局错位。
2. `/competitions` 可展示赛事列表，可按赛事类型和赛道筛选。
3. `/competitions/:slug` 可展示赛事详情，包含介绍、条件、材料、进程、服务。
4. `/news` 可展示资讯列表，可按分类筛选。
5. `/news/:slug` 可展示资讯正文。
6. 未知路由进入 404 页面。

### 10.2 移动端验收

1. 移动端 Header 不展示登录入口。
2. 移动端赛事卡片和详情页不展示报名入口。
3. 移动端 Hero 首屏简洁完整，不出现半截卡片或主要内容被遮挡。
4. Live Competitions 和 Competitions 支持拖动过程跟手动画。
5. Ecosystem、Services、Partners、News 横向滑动释放后可定位到完整卡片。
6. 首页大幅度纵向滑动可定位到下一个/上一个 section，横向滑动区域不误触发。

### 10.3 数据验收

1. 未配置 `VITE_BC_SITE_API_BASE_URL` 时，页面使用 mock 数据正常展示。
2. 配置接口地址后，首页、赛事、资讯优先请求真实接口。
3. 接口失败时页面不白屏，回退到 mock 数据。
4. 赛事和资讯详情通过 `slug` 路由定位。

| 事件 | 触发时机 | 关键字段 |

## 12. 风险与待确认项

1. PM 模板 PDF 当前未能直接抽取文本，如需严格复刻模板字段，需提供可复制文本版或 Word/Markdown 版模板。
2. 移动端是否永久取消报名/登录入口，还是仅本期隐藏，需要产品确认。
3. 赛事报名最终由官网承接还是跳转外部工作台，需要与业务方确认。
4. 资讯内容是否接 CMS，还是由赛事/运营后台统一维护，需要确认。
5. 合作机构、导航菜单、首页统计是否需要后台可配置，需要确认。
6. 分享按钮是否需要接入浏览器原生分享、复制链接或微信分享，需要确认。
7. 赛事状态、赛事类型、资讯类型是否允许后台扩展枚举，需要确认。
