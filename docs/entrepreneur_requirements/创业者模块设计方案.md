# 博创网 · 创业者项目管理模块 — 重设计方案

> 本文档是本次需求的唯一设计基线，依据：会议纪要、当前页面截图（P1–P2）、甬江/宁波参考系统截图（P3–P6）、官方申报书 PDF。
> 字段以**官方申报书**为权威清单；本平台为**宁波平台**，所有"来甬"一律改为"来宁"。

---

## 0. 设计原则（来自会议结论）

1. **先定数据模型，再做 UI。** 当前大部分矛盾（标签、雷达图对比、变更记录、成熟度）都是因为数据结构没定。
2. **结构化优先 + 统一抽象。** 凡"可多条"的对象（成员、论文、专利、经历…）统一用一套结构体机制，不逐个单独造轮子。
3. **字段以申报书为准。** 项目详情、报名表单要填的内容，就是申报书要的内容。
4. **成本意识，不埋坑。** AI 按需触发、接国内模型；做不了或太贵的功能先砍/后置，并在 PRD 里标注成本归属。
5. **硬指标先验真后展示。** 团队规模、融资、专利等未验证不计入雷达图、不作真实展示。

---

## 1. 数据模型（地基）

### 1.1 核心实体

| 实体 | 说明 |
|---|---|
| `Project` 项目 | 创业者的项目本体，可被复制后报名多个大赛 |
| `Applicant` 申报人/带头人 | 项目带头人的完整个人信息（教育、工作、成果、陈述） |
| `RepeatableCollection` 结构化集合 | 统一抽象的"可增删多条"对象（见 1.2） |
| `RegistrationRecord` 报名记录 | 一次报名一条；关联大赛、赛道、提交时的项目快照 |
| `ProjectSnapshot` 项目快照 | 每次保存生成一份结构化快照（JSON），用于回退与 diff |
| `CompetitionTag` 赛道/专业领域 | 三级枚举，由主办方维护，报名时选择 |
| `OrgInfo` 用人单位信息 | 单位基本情况、荣誉、研发与经济效益 |

> **关键：一个 `Project` 可报名多个大赛**（本平台结构，比参考系统"一项目一大赛"更合理，保留）。报名时不复制项目，而是生成一条 `RegistrationRecord` + 一份提交时的 `ProjectSnapshot`。

### 1.2 统一结构化集合（`RepeatableCollection`）

申报书里**所有以下对象都是"可增删多条 + 必填校验 + 列表里以"n 条"聚合显示"**，用同一套 schema 驱动的组件实现：

| 集合 | 主要字段（结构体） |
|---|---|
| 团队成员 TeamMember | 成员类型、姓名、证件类型、证件号、手机号、出生日期、年龄、国籍、分工、背景 |
| 教育经历 Education | 国家、是否全日制、起、止、院校、专业、学历、学位、是否最高学位 |
| 工作经历 Work | 国家、起、止、单位、职务、工作性质、是否来宁前最后工作/回国前最后工作 |
| 主要项目 MajorProject | 项目名称、起止时间、项目来源、承接单位、经费总额、本人角色 |
| 代表性论文 Paper | 标题、作者、发表载体、排名/总数、发表时间、影响因子、是否通讯作者 |
| 代表性专利 Patent | 专利类型、名称、授权国家、专利号、排名/总数、授权时间 |
| 软件著作权 SoftwareCopyright | 软件全称、授权国家、登记号、著作权人、登记批准日期 |
| 主要产品 Product | 产品名称、依托单位、上市时间、影响力与个人贡献（≤100字） |
| 奖励表彰 Award | 获奖时间、名称、颁奖单位、本人排序 |
| 代表性著作 Book | 题目、出版年份、排名/总数、出版社、出版地 |
| 学术会议报告 ConferenceReport | 题目、年份、排名/总数、会议名称、报告类型 |
| 学术任职 AcademicPosition | 组织/期刊名称、职务、任期 |
| 异地创办企业 FoundedCompany | 企业名称、本人角色、本人职务、企业情况、与宁波公司关系 |
| 阶段性目标 ProjectStage | 阶段、起、止、预计投入、阶段性目标（≥2 阶段） |
| 单位荣誉 OrgHonor | 获得时间、荣誉名称、颁发部门（≤5 项） |

**组件统一行为：**
- 表格行展示 + `新增 / 编辑 / 删除` 针对单条结构体。
- **必填字段全部填写才可保存**该条；未通过校验给出红字提示。
- 父级（项目详情/报名表）只显示聚合：`团队成员（15）`、`代表性论文（3）`，点击展开看明细。

### 1.3 字段映射与验证表（节选，完整版按申报书 1:1 落库）

| 平台显示 | 来源（申报书） | 类型 | 必填 | 需验证 | 关联雷达维度 |
|---|---|---|---|---|---|
| 团队规模 | 项目成员条数 | 派生 | — | 是（资料） | 团队规模 |
| 融资额/轮次 | 单位研发与经济效益 | 数值 | 是 | 是（API/人工） | 融资额 |
| 专利数 | 代表性专利条数 + 验收指标 | 派生 | — | 是（附件） | 专利数 |
| 成熟度 | 现有工作基础和条件·项目成熟度 | 枚举/描述 | 是 | 否 | 成熟度 |
| 业务广度 | 专业领域 + 产品/应用场景数 | 派生 | — | 否 | 业务广度（待定逻辑，见 §3.6） |

> 验证字段未通过验证时：雷达图不计入、展示处标注"未验证"。验证触发点见 §3.5。

## 2. 页面设计

### 2.1 项目列表页（一级）

变更：
- **不展示标签**（去掉"医学影像/AI诊断/电子病历"这类自定义标签）。
- "备注名" → **"申报用名"**。
- 每个项目可**上传封面图**；若不传，则**基于关键字段自动生成封面**（项目名 + 申报用名 + 赛道，参考 P3/导出封面效果）。
- 去掉"中式原型概念"等无用展示标签。
- 列表项点击进入二级详情页。

### 2.2 项目详情页（二级）— 排版重构

**核心问题：当前项目详情在最底部，信息模块和功能模块混排。** 重排为"信息在上、功能在下，项目详情上移到报名记录之上"：

```
┌─ 顶部：封面 + 项目名 + 申报用名 + [编辑] [一键报名] ────────────┐
│                                                                  │
│ ① 信息区（项目本体）                                            │
│   · 项目身份：赛道/领域、核心技术、关联企业、团队负责人（无标签）│
│   · 项目详情（完整字段，上移）：项目简介 / 带头人信息 /          │
│     申报人完整信息（教育·工作·成果业绩·个人陈述）/              │
│     团队成员(n) / 用人单位信息 / 附件材料                        │
│                                                                  │
│ ② 数据/评估区                                                   │
│   · 五维成长雷达（当前快照）+ [查看成长对比] 入口               │
│   · AI 建议 / 成长回顾卡片（按需生成，见 §3.3）                 │
│                                                                  │
│ ③ 功能/记录区                                                   │
│   · 报名记录（表格，见 2.4）                                     │
│   · 成长时间线（变更记录 + 快照对比 + 回退，见 2.5）            │
└──────────────────────────────────────────────────────────────┘
```

说明：
- **删除"成长趋势"折线图**（甲方未要求图表），迁移到主办方端数据看板（热力图/大看板/平台管理员可见）。
- 项目详情字段大幅补全，按 §1 数据模型 1:1 落地；信息性模块（身份、详情）与功能性模块（报名、时间线、AI）在版面上分区。

### 2.3 新建 / 编辑项目 & 报名表单 — 横向分板块

参考 P4–P6，改为**横向步骤/Tab 分板块**，阶段可视化，单页不长滚：

```
[封面] [申报人] [项目成员] [项目信息] [成果业绩] [个人陈述] [用人单位] [记录及提交]
  └ 顶部横向步骤条，可见进度
```

各板块字段 = 申报书对应章节（见 §1.2）。其中"项目信息"再设子 Tab：
`项目背景意义 / 项目实施内容 / 阶段性目标 / 工作基础和条件 / 预期贡献及验收指标 / 预期经济效益指标`。

新建项目支持两种入口：
1. **手动填写**（分板块）。
2. **上传本地表格识别导入** —— 用户把本地已有的申报材料（与申报书同构）上传，系统识别填充，目标匹配度 8~9 成，省去重填。**上传优先于复制粘贴**。

> "预报名/基础信息"先用报名界面顶上，后续跑通再查缺补漏。

### 2.4 报名记录（表格形式）

按王营要求，参考 P3 改为表格，列固定为：

| 赛事 | 项目申报名 | 专业领域 | 成员数 | 申报状态 | 破格通道 | 操作 |
|---|---|---|---|---|---|---|
| 大赛名称 | 申报用名 | 所选赛道/领域 | 结构体条数 | 待提交/待审核/通过 | 破格申请入口（对应 P3"直接进入终评/直接认定"） | 查看/复制/预览 |

- 赛道（如"医疗AI/人工智能"）是**大赛的标签**，由主办方在大赛侧配置枚举，报名时选择；不是用户自定义。
- 报名时支持选择本地项目或电脑上的项目上传。

### 2.5 变更记录 & 快照对比（成长时间线）

机制：**每次保存生成一份结构化快照（JSON）**。时间线每个节点支持 `回退` 与 `快照`，并新增 **`查看详情/快照对比`** 按钮。

diff 渲染规则（统一处理所有修改场景，避免逐场景写逻辑）：
- **标量字段**（团队规模、融资额、专利数、成熟度…）：`旧值（删除线）→ 新值`，绿色高亮。
- **长文本**（项目简介、个人陈述…）：原文整体展示，红字标删除、绿字标新增。
- **数组/结构体集合**（团队成员、论文…）：按条目 ID 比对，标注 `新增 / 删除 / 某条某字段变更`（如"李明 身份证号 修改"）。
- **多模块同时修改**：列举各模块（模块名**加粗**），逐块展示其 diff。

必须覆盖的真实场景（验收用）：
1. 只改几个标量数字；2. 只改长文本里几个字；3. 改某个成员的姓名/证件号；4. 新增/删除一个成员；5. 同时改多个模块。

### 2.6 五维成长雷达

- 保留（评价好）。维度：团队规模、融资额、专利数、成熟度、业务广度。
- **补对比维度**：通过 §2.5 的快照机制，支持选两个时间节点对比雷达变化（解决"定版标签没真正定版、缺对比时间维度"的问题）。
- 雷达各维度数值**来自结构化字段且经验证**，不接受用户随手输入的假数。

## 3. 关键交互逻辑

### 3.1 结构体增删改 + 校验
schema 驱动：每类集合定义字段、类型、必填、校验规则；组件据此渲染表单与表格。保存时逐字段校验，未过不存。

### 3.2 快照 diff
保存即存快照；对比时取两份快照做差异计算，按 §2.5 规则渲染。回退 = 用历史快照覆盖当前并记一条新节点。

### 3.3 AI 成长回顾 / 成长对比（按需触发，控成本）
- **触发方式：按需**。用户点 `生成成长回顾` 或在时间线选两节点点 `查看成长对比` 才调用一次。**不做实时、不做定时**（会议已否定：定时体验差、实时成本高且易埋坑）。
- **输入**：只喂结构化快照差异（不喂全文），尽量缩减 token：首次喂初始状态 AI 生成的简要总结，之后只追加增量变更。
- **输出**：
  - 成长回顾 = 综合历史变化，叙述"从创立到现在经历了哪些变化"。
  - 成长对比 = 针对所选两节点做对比分析 + 雷达变化解读。
- **模型**：接**国内模型**（价格稳定、不怕封禁/涨价），不接 Claude Code / 国外模型。
- 卡片输出位置就近显示即可（位置后续可调，逻辑别为位置复杂化）。

### 3.4 本地表格导入识别
上传 → 解析 → 映射到结构化字段 → 预填 → 用户确认。匹配不上的字段留空待填。

### 3.5 数据验证
- **触发点**：报名/提交大赛、进入平台第一轮时做验证。
- **对象**：团队规模（资料）、融资（金额）、专利（附件）等硬指标。
- **方式**：接国内 API 或人工；通过后打"已验证"标记，方计入雷达、方作真实展示。
- 价值：帮主办方省人力初审（产品差异化卖点，优先级提前）。

### 3.6 待明确的逻辑（开发前需拍板）
- **业务广度**维度的计算口径（建议：专业领域覆盖 + 产品/应用场景数派生）。
- **成熟度**维度口径：建议直接沿用申报书"现有工作基础和条件·项目成熟度"的表述，去掉旧的"初试/中试"自造字段，避免与官方不一致。

## 4. 砍掉 / 后置 / 迁移清单

| 处理 | 项 | 原因 |
|---|---|---|
| 删除 | 创业者端"成长趋势"折线图 | 甲方未要求图表，迁主办方看板 |
| 删除 | 自定义标签、"中式原型概念" | 无实际用途，省工作量 |
| 否定 | AI 实时/定时更新方案 | 体验差 + 成本高，改按需触发 |
| 后置 | AI 模拟演练 | 方案太贵/复杂，先砍后做 |
| 迁移 | 成长趋势 → 主办方数据看板（热力图/大看板/管理员可见） | 数据维度更适合官方侧 |

## 5. 术语与字段调整

| 原 | 改为 |
|---|---|
| 来甬（前最后工作、来甬时间…） | **来宁** |
| 备注名 | **申报用名** |
| 自定义标签 | 删除 |
| 专业领域（自由填/自定义） | **三级下拉，与主办方对齐，报名时选** |
| 成熟度（初试/中试…） | 改为贴合申报书的成熟度口径 |

## 6. 导出（闭环）

- 用户按结构化字段填写 → 后端拼装成**官方申报书 Word** → **Word 转 PDF**。
- Word 模板**按申报书 PDF 的版式**制作（已有官方样本，版式有据可依）。
- 导出在**后端**完成，不在前端做。
